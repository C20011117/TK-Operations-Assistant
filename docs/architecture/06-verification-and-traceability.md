# 06 · 完整验收与需求追踪

本章定义实现后的完成标准，以及本次架构文档本身如何核对。它不是 MVP 验收或分期开发清单。当前只有架构文档，以下业务、联调、压测和灾备验收均待实施；确定性安全不变量必须通过，业务效果目标须用真实授权数据校准。

## 1. 12 项产品规格追踪

每项使用固定需求 ID，研发任务、测试与验收记录引用相同 ID。详细数据约束见 [02](02-data-model.md)，流程见 [03](03-matching-and-rag.md)，界面和接口见 [04](04-api-and-frontend.md)，安全运维见 [05](05-security-operations.md)。

### REQ-01 企业资料与产品档案

责任模块：knowledge、identity。核心记录：products、product_versions、product_market_terms、document_versions、knowledge_conflicts。入口：产品页、版本发布、资料审核和冲突处理接口。

验收：上传两份冲突的产品资料，提取结果待确认且能定位原文；人工发布 V1 并用于任务；再发布 V2，新任务可用 V2，旧任务仍指向 V1。未确认硬条件不执行；知识索引未就绪状态清楚；删除源后派生文本按权限及保留政策处理。

### REQ-02 多站点合作任务

责任模块：campaigns、billing。核心记录：campaigns、campaign_markets、criteria_versions、exchange_rate_snapshots。

验收：相同产品创建两个已验证站点任务，采用不同预算、语言、受众与资格条件；两边运行、名单、报价和费用不污染。切换显示不同统计窗口与时区；夏令时变化不重复触发计划。跨站点汇总只在明确转换口径下进行，不输出未经校准的统一原始 GMV 排名。

### REQ-03 多路径达人发现

责任模块：matching、connections、creators。核心记录：search_plans、run_search_paths、candidate_discoveries、provider_calls。

验收：覆盖结构化筛选、产品场景扩展、参考达人、相似商品推广者、企业库复查。相同达人经多路发现只有一个候选且保留每条路径。必要条件缺失进入待核实；零结果与权限失败分开；搜索截断有标记；放宽条件须确认新版本。

### REQ-04 有依据的匹配判断

责任模块：matching、knowledge。核心记录：evidence_items、metric_observations、criterion_evaluations、candidate_evaluations、evaluation_claims。

验收：每条关键肯定事实能定位合法来源和时间窗口，数值由代码比对，推断标明性质。适配程度与证据充分程度各自显示；缺失报价不补零。只有标签时不声称看过视频；授权字幕仅分析实际覆盖片段。模型引用存在但不支持结论时不得发布强结论。

### REQ-05 详情、对比与名单决策

责任模块：shortlists、reporting。核心记录：recommendation_snapshots、shortlist_versions、shortlist_items、budget_scenarios。

验收：当前 BD 依据固定快照自行确认候选并决定合作，列表刷新不改变本人已确认的旧名单。对比同口径指标并显示不可比项、反证和缺失信息。未知报价保持未知；试算明确假设、汇率和时间；重新排序能查看增加、移除及原因。

### REQ-06 我的达人关系库与分类

责任模块：creators、identity。核心记录：creator_accounts、creator_aliases、creator_relationships、creator_classification_events。

验收：本人重复导入和昵称变化不重复建关系；同一达人跨多次合作保留完整产出历史。两名 BD 可以各自建立关系，但不能读取对方的报价、联系、反馈和分类。产出、内容价值、商业表现和维护优先级分开保存，AI 建议由本人确认可改。没有销售数据时仍可记录已验证的内容价值；单轮失利不自动永久淘汰。

### REQ-07 寄样、拍摄指导与视频持续产出

责任模块：collaborations、production、外部动作执行器。核心记录：shipments、content_brief_versions、production_rounds、video_assets/video_versions、video_reviews/feedback_items、video_publications、content_rights、action_confirmations。

验收：同一 BD 在确认合作后寄样，发送产品信息、脚本和镜头要求，回收 V1，给出绑定版本/真实时间位置的修改建议，回收同轮 V2，再约下一条新视频。改脚本保留旧版，后发要求不倒改旧轮次。返修不能重复计作新视频；回收、验收、发布、广告许可互不冒充。缺音轨/字幕/完整帧时明确分析覆盖。本人修改外发内容、收件人或费用后重新确认；结果未知不盲重发。受限达人提交链接不能读取或提交到其他轮次。

### REQ-08 结果与受控企业经验

责任模块：learning、collaborations。核心记录：outcome_observations、rule_proposals、rule_versions、rule_set_versions。

验收：区分未联系、未回复、报价过高、档期不符、完成发布与未知销售。产品、价格、库存和样品背景保留。模型建议未经批准不改变硬筛；批准后可追查影响的新运行；撤销后新任务停用，旧快照保留历史标识。企业之间不共享私有偏好。

### REQ-09 重点达人维护与每日待办

责任模块：creators、automation、jobs。核心记录：maintenance_plans、maintenance_actions、refresh_schedules、schedule_ticks、notifications。

验收：本人按有依据的分类安排维护优先级、下次联系目的、适合产品和约拍方向；从维护任务可直接进入新一轮确认。待寄样、待回收、待反馈和重点维护按真人实际工作呈现，不出现分配任务入口。暂停合作或拒绝继续后不持续自动催促。重复 tick 不重复执行，时区、静默、额度、暂停和连接失效都正确显示；旧数据不冒充刷新完成。

### REQ-10 数据连接与费用控制

责任模块：connections、billing。核心记录：credential_versions、capability_snapshots、rights_policy_versions、provider_calls、call_attempts、usage_reservations、usage_ledger。

验收：网页会员、REST 和 MCP 权限独立验证。只显示已实际验证的站点字段；密钥不出现在模型、浏览器响应、日志或图状态中。并发查询共用额度上限；预占、实际消费、估计与未知分开；超时可能扣费不按零释放。读不到供应方余额时只显示应用已记录用量。

### REQ-11 效果分析与业务交付

责任模块：reporting、billing。核心记录：metric_definitions、report_runs、report_artifacts、export_jobs、share_links。

验收：同一报告快照可回到分母、去重键、窗口和源记录。供应方估计与店铺真实订单分开，退款调整可追查；GMV 不显示成利润。导出只含有权限及使用许可字段，下载时复核权限，撤销分享立即阻断新访问。

### REQ-12 账号、运营与可靠性

责任模块：identity、billing、jobs、audit、data_lifecycle。核心记录：sessions、memberships、plan_versions、tenant_subscriptions、billing_records、deletion_requests、audit_events。

验收：注册、恢复、邀请、MFA、企业切换、套餐、席位、续费取消、导出、退出全链路可用。错误有恢复路径；队列重建不会丢任务；旧备份恢复先重放删除和撤权；运行角色无法绕过 RLS；生产数据不能进入未授权的模型、日志或测试环境。

## 2. 核心端到端验收场景

### E2E-01 一个 BD 完成两条新视频并维护达人

同一名 BD 建立产品资料与找人任务，选中合适达人；确认合作及寄样；并行准备产品信息、脚本、镜头要求和参考风格；创建第一拍摄轮次，回收 V1，检查具体问题并发送本人确认的意见；回收 V2 并验收。随后根据实际产出与内容价值更新分类，设维护计划；到期联系并确认下一条要求，创建第二轮并回收新视频。最后查看两条新视频与一次返修的独立记录及实际费用。

通过标准：全程不依赖负责人审名单、认领、分配或其他员工接力；旧脚本、反馈和视频版本可追查；两轮产出计为两条，第一轮 V1/V2 不算两条；内容价值与未知销售分开；维护促成下一轮动作，不能仅变成静态标签。

### E2E-02 缺数据与真实零结果

分别注入真实空列表、403、额度不足、部分字段缺失、响应 schema 变化、限流和请求超时。用户看到不同原因和可行下一步。即使只得到 partial 结果，所有已展示推荐仍具有证据和数据时效；无法确认带货资格的候选不计入已合格。

### E2E-03 版本、权限和人员变化

匹配执行中更新产品、撤销资料权限、关闭连接或移除发起用户。已发出的请求如实记录；后续敏感步骤停止或等待新授权。旧结果对无权限者不可见，原主体权限恢复后仍需复核执行范围，不开放他人接手私有业务的日常流程。历史名单不被新版本覆盖，删除证据后显示不可用而不是重建原文。

### E2E-04 付费与外发的不确定结果

让供应方执行成功后丢失响应，再让 Worker 崩溃。恢复首先读取 provider_calls / attempts / 本人确认与账本，不重复网络动作。供应方支持查询时核对；不支持时进入人工核查。费用保留 unknown 和必要预占，不能以租约到期自动释放。

### E2E-05 删除、导出与灾备恢复

企业 A 删除资料、撤销分享和成员；在隔离环境恢复旧备份；恢复前重放独立删除/撤权记录、清理派生物并关闭外发。验证 A 已删除资料不重新出现、企业 B 的资料不受损、旧外发不重发、旧 Key 不重新激活。达到正式 RPO/RTO 必须有实际演练时间与日志。

### E2E-06 视频回收、反馈和下一条的边界

同一上传重复完成、相同文件重复提交、旧视频再次导入、反馈发出后轮次要求改变、达人只给发布链接而未给原片、媒体解析缺音轨、建议引用不存在时间码，均应有确定结果。受限提交链接失效后不能继续获取上传许可；已开始上传也必须在 complete 再检查。已通过版本与返修版独立，撤回验收会影响当前可用状态但保留历史事件。

通过标准：不重复创建视频产出，不把平台链接虚构绑定到某个文件版本，不把文字 RAG 当视觉验证；BD 可以手动审核并继续工作，不因某个模型失败失去已回收的文件。

### E2E-07 分类和维护可解释、可更正

准备持续产出但商业数据缺失、偶有高质量素材但档期不稳、已知有商业表现、尚未观察成熟等关系记录。AI 分维度建议，BD 可确认或修改维护优先级。更正错误结果后重新计算建议，保留原因；不自动群发，不把一次未回复永久拉黑。其他 BD 的记录不参与这些判断。

## 3. 数据契约与故障注入测试

### 3.1 确定性规则测试

测试金额精度、汇率版本、不同窗口不可比、date 与 timestamp、DST、三态聚合、规则作用域冲突、版本绑定、状态转换、幂等 request hash。覆盖 null、真实零、负调整、源过期和冲突资料。只测试业务不变量，不为了覆盖率复制实现细节。

### 3.2 真实数据库集成测试

使用真实 PostgreSQL + pgvector，不用 SQLite 替代 RLS、复合 FK、事务和锁测试。使用实际 app_runtime 数据库角色测试读写，另测表 owner / 超级用户不能用于应用配置。检索包含跨企业相似文本、同企业私有资料和删除资料，确保都不会进入未经许可的 Prompt。

并发测试覆盖相同轮次重复提交、同一版本重复验收、提交链接配额、跨层预算预占、幂等任务、过期 lease 接管、Outbox 发布后崩溃、旧 Worker 迟到结果与重复 webhook。所有网络副作用通过可记录是否执行的测试供应方模拟精确故障时点。

### 3.3 供应方契约测试

每个正式支持的 `connection × market × operation` 保存验证清单：实际字段、空值语义、ID 范围、地区含义、时间/币种/窗口、分页/截断、限流、收费、错误、重试和结果核对能力。使用获准脱敏 fixture 做持续回归，凭据与原文不进仓库。

真实授权账号联调验证能力，fixture 只证明适配器能解析样本。供应方变更触发能力降级和契约复测；未经验证的站点选项显示待接入或不可用。

### 3.4 AI 和检索评测

评测集按企业许可、市场、产品类目、语言、证据完整性与冷热启动分层，按任务和时间切分；找人阶段不能看到合作后结果。保存评测输入哈希、资料时点、人工标签、争议裁定、模型/Prompt/规则/检索版本与调用成本。

重点测必要硬条件误通过、未知保留、引用定位、事实支持、冲突识别、产品型号保真、推荐相关性和单位合格候选成本。模型升级或参数变更须运行对应回归；只检查 JSON 可解析不能证明建议正确。

### 3.5 前端与无障碍测试

覆盖企业切换缓存清理、私有关系隔离、412 冲突、SSE 重连、等待输入、取消竞争、部分失败、过期快照、视频版本切换、带位置反馈、下一轮创建及导出权限。键盘可完成表单、视频意见和本人确认；错误能定位到字段；状态不只靠颜色表达。

### 3.6 运维测试

记录生产候选规模、企业数、活跃用户、每秒查询、每任务候选量、文件尺寸和缓存命中等负载条件，测试 API / Worker / DB / provider 限流相互影响。执行 Redis 丢失、DB 失联、KMS 失效、Worker 终止、schema 变更、对象缺失、费用核对积压和恢复演练。不得只在空数据库压测后宣称企业规模能力。

## 4. 业务指标的具体口径

指标采用版本化定义，报告固定 `definition_version + data_cutoff + cohort + attribution_window + source_snapshot`。不同统计口径不得在同一曲线上无提示拼接。

- **合格候选数量**：按单任务市场＋企业内 canonical creator 去重，所有必需硬条件 pass 的候选数；unknown 和 failed 不计入。
- **寄样后首条可用视频耗时**：从实际发出样品到 BD 首次确认视频符合该轮交付要求；签收后耗时另列，不能混用。未回收/未验收作为未完成样本，并报完成率，不能静默排除慢任务。
- **新视频产出与返修**：按 owner、relationship、production_round 去重；同资产 V1/V2/V3 合计一条新视频，另记返修次数和耗时。素材回收、验收通过和已发布各自计数。
- **持续产出率**：固定 cohort 中完成至少两轮独立新视频的达人数 / 已确认继续产出约定且相应观察窗口成熟的达人数；同时报告从首次合作进入继续约拍的比例，避免只挑成功者当分母。
- **内容可用率**：本人按该轮明确标准验收通过的去重新视频数 / 已回收且审核窗口成熟的视频数；尚待审核另列。投广告是否可用由广告授权及用途另判，不能只凭内容审核结果推定。
- **可用视频成本**：同一明确合作/窗口下的样品、运费、固定费用、确认佣金及分摊工具成本 / 去重可用视频数；各项未知保持未知，分母0显示不可计算。分摊方法和币种/汇率版本可回查，不把共用成本在每轮重复算完整一次。
- **有价值达人再次产出**：使用期初已经由 BD 确认的分类 cohort，统计窗口内再次取得独立新视频的关系数与比例；不能事后只把成功者归为重点维护来美化结果。与主动维护次数一起观察，不将相关性宣称为因果提升。
- **找到目标数量合格候选的时间**：从用户确认并启动有效任务，到首次形成满足目标数量且证据可用的名单。未达目标任务保留为未完成 / 截尾，另报完成率，不能从耗时样本中静默删除。系统墙钟时间与 BD 主动操作时间分开，后者需经允许的操作埋点估算。
- **BD 采用率**：固定运行 cohort 中，被 BD 明确保留的去重合格候选数 / 已展示的去重合格候选数。待核实组另报；只被自动写入短名单不算人工采用。
- **联系率**：已确认至少一次实际联系的候选 / 本人明确选择进入联系阶段且观察窗口成熟的候选；草稿、计划联系、发送 unknown 不算确认联系。
- **回复率**：在规定观察窗口内有明确回复的去重合作对象 / 已确认成功联系且观察窗口成熟的对象。主动回复、系统自动回执分开；未成熟任务单列。
- **达成合作和发布率**：分别以已确认联系 / 已确认合作为明确分母，保留条款确认和发布证据。缺内容链接不自动算未发布，应列未知。
- **单位合格候选成本**：同任务市场下已核对的数据与模型调用成本 / 去重合格候选数；分母0时显示不可计算。估计与待核对费用另列区间，不混成精确费用。
- **真实使用复用**：BD 在观察期实际推进的合作和新视频轮次数，以及回访并完成有效动作的 BD 数；排除测试、重复提交和纯重试。周期自动刷新单列，不能伪装为主动使用。
- **推荐风险指标**：必要硬条件误通过、无依据关键事实、重复候选、过期资料、引用不可用与人工纠错次数；同时记录样本量和评估范围。
